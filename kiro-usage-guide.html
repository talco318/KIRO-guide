מה זה Kiro? — סקירה כללית

בקצרה

Kiro הוא סביבת פיתוח (IDE) מבוססת בינה מלאכותית שנבנתה כדי לעזור למפתחים לכתוב קוד טוב יותר, מהר יותר. Kiro משלב עורך קוד מלא עם עוזר AI חכם שמבין את הפרויקט שלכם.

מה Kiro יכול לעשות?

  • ✍️ לכתוב ולערוך קוד עבורכם
  • 🔍 לנתח ולהבין קוד קיים
  • 🐛 לזהות ולתקן באגים
  • 📁 ליצור, לערוך ולמחוק קבצים
  • 💻 להריץ פקודות בטרמינל
  • 📋 לתכנן פיצ'רים שלמים (Specs)
  • 🔄 להגדיר אוטומציות (Hooks)
  • 🌐 לחפש מידע באינטרנט
  • 🏗️ לעזור עם תשתיות וקונפיגורציות
💡 Kiro מבוסס על VS Code, כך שאם אתם מכירים VS Code — תרגישו בבית.

הכרת הממשק

אזורי הממשק העיקריים

  • עורך הקוד (מרכז) — כאן כותבים ועורכים קוד, כמו בכל IDE
  • סייר הקבצים (שמאל) — עץ הקבצים והתיקיות של הפרויקט
  • חלונית הצ'אט (ימין) — כאן מתקשרים עם ה-AI של Kiro
  • טרמינל (למטה) — להרצת פקודות
  • פאנל Kiro (ימין) — Specs, Hooks, ו-Steering

פתיחת חלונית הצ'אט

אם חלונית הצ'אט לא מוצגת:

  1. לחצו על אייקון Kiro בסרגל הצד
  2. או השתמשו בקיצור: Ctrl + Alt + I

עבודה עם Chat (צ'אט)

איך לשאול שאלות

פשוט כתבו את הבקשה שלכם בשפה טבעית — עברית או אנגלית. Kiro מבין את שתי השפות.

דוגמה לשיחה:
Create a function that validates email addresses
הנה פונקציה שמאמתת כתובות אימייל... (Kiro יכתוב את הקוד ויציע להוסיף אותו לקובץ)

שימוש ב-Context Keys (#)

ניתן להפנות את Kiro לקבצים ומידע ספציפי באמצעות סימן #:

פקודה מה זה עושה
#File מפנה לקובץ ספציפי בפרויקט
#Folder מפנה לתיקייה שלמה
#Problems מציג שגיאות ואזהרות בקובץ הנוכחי
#Terminal מפנה לפלט הטרמינל
#Git Diff מציג את השינויים שביצעתם ב-Git
דוגמה לשימוש ב-#File:
תסביר לי מה עושה #File src/utils/helpers.ts
הקובץ הזה מכיל פונקציות עזר ש...

צירוף תמונות ומסמכים

  • תמונות: גררו תמונה לתוך הצ'אט, או לחצו על אייקון התמונה
  • מסמכים: גררו PDF, DOCX וכו' לתוך הצ'אט, או לחצו על אייקון הצירוף

Kiro יקרא ויבין את התוכן ויוכל לעזור לכם על בסיסו.

💡 טיפ: ככל שתהיו יותר ספציפיים בבקשה, כך התוצאה תהיה טובה יותר. במקום "תתקן את הקוד", כתבו "תתקן את הבאג בפונקציה X שגורם ל-Y".

מצבי עבודה — Autopilot vs Supervised

שני מצבי עבודה

Kiro מציע שני מצבים לעבודה עם ה-AI:

🤖 Autopilot

Kiro פועל באופן עצמאי

מבצע שינויים בקבצים ללא אישור מראש. מתאים למשימות שאתם בטוחים בהן.

👁️ Supervised

אתם מאשרים כל שינוי

Kiro מציע שינויים ואתם מחליטים אם לקבל או לדחות. מתאים לעבודה זהירה.

מתי להשתמש בכל מצב?

  • Autopilot — כשאתם עובדים על משימה ברורה, יצירת קבצים חדשים, או refactoring פשוט
  • Supervised — כשאתם עובדים על קוד רגיש, production, או כשאתם רוצים ללמוד מהשינויים
⚠️ המלצה: אם אתם חדשים ב-Kiro, התחילו במצב Supervised כדי להבין איך ה-AI עובד, ועברו ל-Autopilot כשאתם מרגישים בנוח.

עבודה עם קבצים ותיקיות

פתיחת פרויקט

  1. לחצו File → Open Folder
  2. בחרו את תיקיית הפרויקט שלכם
  3. Kiro יטען את הפרויקט ויהיה מוכן לעזור

מה Kiro יכול לעשות עם קבצים

  • 📝 ליצור קבצים חדשים
  • ✏️ לערוך קבצים קיימים
  • 🗑️ למחוק קבצים
  • 📂 להעביר ולשנות שמות קבצים (עם עדכון אוטומטי של imports)
  • 🔍 לחפש בתוך קבצים

דוגמאות לבקשות

  • "צור קובץ חדש בשם utils.ts בתיקיית src"
  • "הוסף פונקציה לקובץ #File src/helpers.ts"
  • "שנה את שם הפונקציה calculateTotal ל-computeTotal"
  • "מחק את הקובץ old-config.json"
✅ Kiro מעדכן אוטומטית את כל ה-imports וההפניות כשמשנים שם או מעבירים קובץ.

Specs — תכנון פיצ'רים

מה זה Spec?

Spec (מפרט) הוא דרך מובנית לתכנן ולבנות פיצ'ר חדש עם Kiro. במקום לקפוץ ישר לקוד, Spec מאפשר לכם:

  1. להגדיר דרישות (Requirements)
  2. לתכנן את הארכיטקטורה (Design)
  3. ליצור רשימת משימות (Tasks)
  4. לבצע את המשימות אחת-אחת

איך ליצור Spec חדש

  1. פתחו את חלונית הצ'אט
  2. תארו את הפיצ'ר שאתם רוצים לבנות, למשל: "אני רוצה להוסיף מערכת אימות משתמשים"
  3. Kiro ישאל אתכם אם זה פיצ'ר חדש או תיקון באג
  4. בחרו את סוג ה-Spec ואת הגישה (Requirements first / Design first)
  5. Kiro ייצור את המסמכים ויבקש את אישורכם בכל שלב

מבנה ה-Spec

כל Spec נשמר בתיקייה .kiro/specs/{feature-name}/ ומכיל:

קובץ תוכן
requirements.md דרישות הפיצ'ר — מה צריך לעשות
design.md תכנון טכני — איך לעשות את זה
tasks.md רשימת משימות — שלבי הביצוע

הרצת משימות מה-Spec

אחרי שה-Spec מוכן, תוכלו לבקש מ-Kiro לבצע את המשימות:

  • "בצע את משימה 1" — מבצע משימה ספציפית
  • "בצע את כל המשימות" — מבצע את כולן ברצף
💡 טיפ: Specs מאפשרים לכם לשלוט בתהליך הפיתוח. אתם מאשרים כל שלב לפני שממשיכים הלאה.

Hooks — אוטומציות

מה זה Hook?

Hook הוא אוטומציה שמפעילה פעולה כשאירוע מסוים קורה. למשל: הרצת lint אוטומטית כשנשמר קובץ TypeScript.

סוגי אירועים (Triggers)

אירוע מתי מופעל
fileEdited כשנשמר קובץ
fileCreated כשנוצר קובץ חדש
fileDeleted כשנמחק קובץ
promptSubmit כשנשלחת הודעה לצ'אט
userTriggered כשלוחצים על כפתור ידני

סוגי פעולות (Actions)

  • askAgent — שולח הודעה ל-AI (למשל: "בדוק שהקוד עומד בסטנדרטים")
  • runCommand — מריץ פקודה בטרמינל (למשל: npm run lint)

דוגמה: Lint אוטומטי בשמירה

Hook שמריץ lint בכל פעם שנשמר קובץ TypeScript:

{ "name": "Lint on Save", "version": "1.0.0", "when": { "type": "fileEdited", "patterns": ["*.ts", "*.tsx"] }, "then": { "type": "runCommand", "command": "npm run lint" } }

איך ליצור Hook

  1. פתחו את ה-Command Palette (Ctrl + Shift + P)
  2. חפשו "Open Kiro Hook UI"
  3. או: בקשו מ-Kiro בצ'אט — "צור לי hook שמריץ tests כשנשמר קובץ"

Steering — הנחיות מותאמות

מה זה Steering?

Steering הם קבצי הנחיות שמלמדים את Kiro על הסטנדרטים, הנורמות, והמידע הספציפי של הפרויקט שלכם. הם נשמרים בתיקייה .kiro/steering/.

למה זה שימושי?

  • 📏 הגדרת סטנדרטים של קוד לצוות
  • 📚 מידע על הפרויקט שKiro צריך לדעת
  • 🔧 הוראות build/test/deploy ספציפיות
  • 🎨 כללי עיצוב ו-naming conventions

סוגי Steering

סוג מתי נטען שימוש
Always (ברירת מחדל) תמיד, בכל אינטראקציה כללים גלובליים לפרויקט
fileMatch כשקובץ מסוים נקרא כללים ספציפיים לסוג קובץ
manual כשמפנים אליו עם # מידע שרלוונטי רק לפעמים

דוגמה: קובץ Steering בסיסי

קובץ .kiro/steering/coding-standards.md:

# סטנדרטים לקוד - השתמשו ב-TypeScript strict mode - כל פונקציה חייבת JSDoc - שמות משתנים ב-camelCase - שמות קומפוננטות ב-PascalCase - אין any — תמיד הגדירו טיפוסים

טיפים ושיטות עבודה מומלצות

🎯 היו ספציפיים

במקום "תתקן את הקוד", כתבו "תתקן את הבאג בפונקציה validateEmail שלא מזהה דומיינים עם נקודות"

📎 צרפו הקשר

השתמשו ב-#File ו-#Folder כדי לתת ל-Kiro הקשר. ככל שיש יותר הקשר, התוצאה טובה יותר.

🔄 עבדו בשלבים

במקום לבקש פיצ'ר שלם בבת אחת, חלקו למשימות קטנות. זה נותן תוצאות טובות יותר.

✅ בדקו את הקוד

תמיד עברו על הקוד ש-Kiro כותב. הוא טוב, אבל אתם מכירים את הפרויקט הכי טוב.

📋 השתמשו ב-Specs

לפיצ'רים גדולים, השתמשו ב-Specs. זה חוסך זמן ומבטיח שהתוצאה תהיה מסודרת.

🔧 הגדירו Steering

אם יש לכם סטנדרטים קבועים, הגדירו אותם ב-Steering כדי ש-Kiro יעקוב אחריהם אוטומטית.

🚀 זכרו: Kiro הוא שותף לעבודה, לא תחליף. השתמשו בו כדי להאיץ את העבודה שלכם, אבל תמיד שמרו על שליטה ובקרה על הקוד.
